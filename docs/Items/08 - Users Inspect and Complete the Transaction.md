# Users Inspect and Complete the Transaction

## Purpose
Give each recipient a clear chance to check their item before the transaction closes.

## Inspection Period
For shipped items, start the 48-hour default inspection window only after carrier-confirmed delivery or support-verified delivery. A user-entered tracking status or manual “delivered” claim is insufficient. Show the exact deadline, time zone, and evidence source. In a two-way swap, track a separate delivery and inspection window for each received item; one leg does not start or complete the other.

For local meetups, users inspect the received item together before each separately confirms handover. One participant’s confirmation alone does not complete a disputed handover.

## Recipient Actions
- **Accept item**
- **Report a problem**
- **Need more time** (request support review; it is not an automatic extension)

A recipient who needs more time chooses a reason, such as a delayed delivery or inability to inspect. Show the revised deadline if the request is approved.

## Reminders and Completion
1. Notify the recipient when the inspection period starts.
2. Send a reminder before the deadline.
3. If no problem is reported by the deadline, mark that item leg **No issue reported**. Hold payout until acceptance or the inspection deadline only where the approved provider supports it.
4. Complete the overall swap only when every item leg is accepted or reaches its inspection deadline with no open claim, required handover confirmations are present, and payment requirements are satisfied.
5. If the provider cannot support the required payout hold for an online transaction type, disable online checkout for that type.
6. Notify both users of completion and invite reviews.

A review should only become available after the transaction reaches a completion state.

## Completed Transaction Screen
Show:
- Items exchanged
- Any cash amount paid
- Handover method
- Completion date
- Review actions
- Report a problem or get help link

## Evidence-Based Claims and Returns
- A claim identifies the item, problem, and requested remedy. Gather listing and contract snapshots, pre-shipment and packaging photos, carrier events, separate handover confirmations, and received-item evidence.
- Give the other participant a clear opportunity to respond. Preserve evidence versions and timestamps. A bare assertion is not verified delivery, defect, or return.
- Support compares evidence with the exact listing snapshot, disclosed condition, accepted contract version, and applicable location profile.
- Possible outcomes include no change, a tracked return with deadlines, return-and-refund through an approved payment flow, or another remedy agreed by both users and permitted by policy.
- Hold payout only if the approved provider permits it. If SWAPY cannot support the required hold, disable online checkout before the transaction begins.
- Physical return and cash refund are separate steps. Record return tracking and confirmation, then process money through provider-supported refund/reversal rules. Explain any limits honestly.
- Keep unresolved claims open for support review. Do not auto-complete, auto-refund, or release disputed inventory solely because time elapsed.

## Justification
An explicit inspection period tells users when to check their item and how to raise a concern. Reminders reduce missed deadlines. Making reviews available only after completion ties feedback to an actual transaction.
